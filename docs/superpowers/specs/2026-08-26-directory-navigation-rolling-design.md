# 腾讯文档巡检目录固定滚动设计

## 目标

将腾讯文档 `DWHBzb1ZFZWhFREZa` 的“目录”Sheet（`BB08J2`）中 `M1:O8` 固定为巡检导航区。导航区始终展示汇总页、最新五个完整周周期和归档页，并为所有报告名称设置指向实际 Sheet 的链接。

## 固定布局

| 行 | M 列 | N 列 | O 列 |
|---|---|---|---|
| 1 | 周期 | 慢服务扫描报告 | 慢SQL扫描报告 |
| 2 | 空 | 慢服务汇总（链接） | 慢SQL汇总（链接） |
| 3–7 | 最近五个周期 | 对应慢服务周 Sheet（链接） | 对应慢SQL周 Sheet（链接） |
| 8 | 空 | 慢服务归档（链接） | 慢SQL归档（链接） |

周周期按“上旧下新”排列。导航维护不得修改 `M1:O8` 之外的任何单元格、链接或样式。

## 周期识别

- 只识别名称严格匹配 `慢服务MMDD-MMDD` 和 `慢SQLMMDD-MMDD` 的 Sheet。
- 只有慢服务、慢 SQL 两张 Sheet 同时存在的周期才可进入目录。
- 包含“作废”“汇总”“归档”的 Sheet 不参与周周期识别。
- 对完整周期按实际周起始日期排序，取最新五个；目录第 3 行放五周中最旧周期，第 7 行放最新周期。
- 缺少任一类型、周期重复或目标固定 Sheet ID/名称不匹配时停止更新，不写入不完整目录。

## 链接规则

- 第 2 行链接到现有汇总 Sheet：`慢服务汇总`、`慢SQL汇总`。
- 第 3–7 行链接到每个周期对应的慢服务、慢 SQL Sheet。
- 第 8 行链接到现有归档 Sheet：`慢服务归档`、`慢SQL归档`。
- 每次维护都根据当前 `get_sheet_info` 返回的实际 Sheet ID 重建 N2:O8 的 14 个链接，不复用历史链接 ID。
- 单元格显示文本必须与目标 Sheet 名称完全一致。

## 工作流集成

### week-tencent-upload

新周的两张 Sheet 创建完成后，立即重建 `M1:O8`。如果此时工作簿短暂存在六个完整周周期，目录只展示最新五周，最旧周 Sheet 暂时保留但不再显示，等待归档流程处理。

### week-tencent-archive

归档写入、双归档内容校验、旧周 Sheet 删除全部成功后，再次重建并校验 `M1:O8`。目录更新失败不应回滚已经通过内容校验的归档，但必须明确报错，且不得继续修改其他区域。

## 写入与验证

1. 读取并保存 `M1:O8` 之外的同行哨兵值，或通过严格限定写入范围保证不越界。
2. 在内存中生成完整的 8×3 目标矩阵和 14 个链接映射。
3. 先校验所有目标 Sheet 均存在且名称、ID匹配，再写入 `M1:O8`。
4. 为 N2:O8 中的报告名称设置链接。
5. 回读 `M1:O8`，验证文本、周期顺序、链接目标和单元格坐标完全一致。
6. 任一步失败均显式报错；重复执行得到相同结果，不产生第 9 行及以下的目录记录。

## 兼容与迁移

- 当前 `M1:O8` 已符合目标文本布局，且 N2:O8 的 14 个链接均指向对应 Sheet；首次运行应为幂等重建。
- 原有“寻找下一个空行并追加”的目录逻辑停止用于周巡检导航。
- 归档流程不再按历史周期逐行清空目录；改为归档完成后统一重建固定导航区。

## 测试要求

- 五周正常布局按上旧下新生成。
- 第六周出现时只保留最新五周，且不会写入第 9 行。
- 汇总、归档和作废 Sheet 不会被误识别为周周期。
- 不完整周期阻止目录更新。
- Sheet ID 变化后链接使用新 ID。
- 上传和归档中断后可安全重跑，目录不会重复或错位。
- 回读发现文本、顺序或链接不一致时失败。
- 写入范围严格限定为 `M1:O8`。
